# Design

## Context

동기와 범위는 proposal.md, 요구사항은 `specs/`를 따른다. 현재 상태:

- `SourceCard.tsx`는 `[N]` 번호 칩, 노란 별 5개(`role="img"`, `aria-label="평점 N점"`)와 평점 숫자, 작성자 텍스트, 제목, 내용 전체를 그린다. 내용은 길이 제한이 없다.
- `SourceAccordion.tsx`는 카드를 `hidden` 속성이 걸린 패널 안에 항상 렌더링한다(접힌 동안은 `display: none`).
- `SourceReview`(`id, title, content, rating, author, date, score`)에 `date`와 `score`가 이미 있고 API는 바꾸지 않는다. `score`는 0.65~0.98로 정규화한 표시용 값이며 코사인 유사도가 아니다(main 스펙 `review-rag-chat`).
- Tailwind v4, `lucide-react` 사용 중. 컴포넌트 테스트는 jsdom(레이아웃 계산이 없음)이고, 실제 브라우저 확인은 임시 폴더의 `puppeteer-core`로 한다.

## Goals / Non-Goals

**Goals:**
- 카드 하나로 "누가, 언제, 몇 점, 얼마나 관련 있는지, 무슨 내용인지"를 한눈에 보여준다.
- 긴 리뷰가 카드를 길게 늘리지 않되 원문 전체를 읽을 수 있다.
- 키보드와 스크린리더로 같은 정보에 접근할 수 있다.

**Non-Goals:**
- API·타입·점수 산식 변경, 정렬·필터, 복사·공유.

## Decisions

### 1. 표기 변환은 순수 함수로 분리 (`src/lib/format.ts`)
- `formatReviewDate(date)`: `^\d{4}-\d{2}-\d{2}` 형식이면 `YYYY.MM.DD`, 아니면 `trim()`한 원문, 비었으면 `null`. 시간대 변환이 없는 문자열 처리라 날짜가 하루 밀리는 문제가 없다(`Date`로 파싱하지 않는다).
- `toMatchPercent(score)`: 숫자가 아니면 `null`, 아니면 `Math.round(clamp(score, 0, 1) * 100)`. 입력이 0.885면 89가 되도록 부동소수 오차를 피하려고 `Math.round(score * 100)`을 쓰고, 경계 테스트(0.885, 1.2, -0.1, NaN)를 둔다.
- 대안: 컴포넌트 안에서 인라인 계산 → 경계값 테스트가 어렵고 `SourceCard`가 커져 기각.

### 2. 별점은 기존 구현 유지
이미 노란 채움 별(`fill-amber-400`)과 빈 별 5개, `role="img"`와 접근 가능한 이름을 갖추고 있다. 채움 개수 계산(`round`, 0~5 제한)을 `format.ts`가 아니라 `SourceCard` 안에 두되 요구사항 시나리오(7점, -1점)를 테스트로 고정한다.

### 3. 메타 태그는 작은 알약 모양, 아이콘 포함
작성자 `User`, 작성일 `Calendar` 아이콘(`aria-hidden`)에 텍스트를 붙인다. 값이 없으면 태그 자체를 렌더링하지 않는다. 별점·번호 칩은 첫 줄, 일치율 배지는 같은 줄 오른쪽 끝(`ml-auto`), 메타 태그는 제목 위 줄에 둔다. 좁은 화면에서는 `flex-wrap`으로 줄바꿈한다.

### 4. 말줄임·펼치기는 `ExpandableText` 컴포넌트로 격리
- 접힌 상태: `line-clamp-2`. 펼친 상태: 클램프 제거.
- **넘침 감지**: 접힌 상태에서 `el.scrollHeight > el.clientHeight + 1`이면 말줄임이 발생한 것이다. 마운트 시 `useLayoutEffect`로 한 번, 이후에는 `ResizeObserver`로 크기 변화(창 너비 변화, `display: none` → 표시 전환)마다 다시 잰다. 아코디언이 닫혀 있는 동안 카드의 크기는 0이라 측정값이 의미 없으므로, 패널이 열려 크기가 생기는 순간 `ResizeObserver`가 다시 재게 한다.
- **조작**: 넘칠 때만 "더보기"/"접기" 버튼(`aria-expanded`, `ChevronDown`)을 보이고, 본문 텍스트 클릭도 같은 토글을 한다(본문은 포커스 대상이 아니고 버튼이 키보드 경로다). 펼친 상태에서는 넘침 여부와 상관없이 "접기"를 유지해 너비가 늘어나도 버튼이 사라지지 않게 한다.
- `ResizeObserver`가 없는 환경에서는 마운트 시 한 번만 측정한다(throw하지 않음).
- 대안 A: 글자 수로 판단(예: 80자 초과) → 폰트·너비에 따라 틀려서 기각. 대안 B: 항상 버튼 표시 → 짧은 내용에서 무의미한 조작이 되어 기각.

### 5. 일치율 배지와 의미 표기
`Target` 아이콘 + `"{N}% 일치"`. 점수가 0.65~0.98이므로 배지는 대부분 65%~98% 범위로 보인다. 오해를 줄이려고 `title`(툴팁)에 "검색 점수 0.89 · 키워드 관련도와 도움이 됨 수를 조합한 표시용 점수이며 의미 유사도는 아닙니다"를 넣고, `aria-label`에도 같은 설명을 넣어 스크린리더가 "89% 일치"와 설명을 함께 읽게 한다. 색은 점수 구간별로 달리하지 않는다(구간별 색은 정확도가 있는 것처럼 보이게 한다).

### 6. 테스트 전략
- `format.ts`: 순수 함수 단위 테스트.
- `SourceCard`/`ExpandableText`: jsdom은 `scrollHeight`/`clientHeight`가 0이라 `Object.defineProperty`로 값을 주입하고 `ResizeObserver`를 스텁해 넘침·너비 변화를 흉내 낸다.
- 실제 레이아웃(말줄임이 정말 2줄에서 잘리는지, 펼치면 높이가 늘어나는지, 닫힌 아코디언을 열 때 버튼이 나타나는지)은 Chrome으로 직접 확인한다.

## Risks / Trade-offs

- [일치율 배지가 의미 유사도로 오해됨. 키워드 매칭이 없어 인기 리뷰가 기본 반환된 경우에도 높은 퍼센트가 표시됨] → 툴팁·접근성 이름으로 의미를 밝힌다. 기본 반환 여부를 응답이 알려주지 않아 UI가 구분하지 못한다. 필요하면 후속 변경에서 응답에 플래그를 추가한다.
- [터치 기기에서는 `title` 툴팁을 볼 수 없음] → 접근성 이름은 제공되지만 시각적 설명은 없다. 필요하면 후속 변경에서 탭 시 설명을 보여주는 방식을 검토한다.
- [넘침 측정이 레이아웃 변화(폰트 로딩 등)를 놓침] → `ResizeObserver`가 요소 크기 변화를 잡고, 폰트 로딩 후 줄바꿈이 달라지면 높이가 바뀌어 다시 측정된다.
- [jsdom에서는 실제 말줄임을 검증할 수 없음] → 브라우저 확인 태스크를 별도로 둔다.
- [카드가 닫힌 패널 안에서 측정하면 항상 넘침 없음으로 판정] → 크기 0 → 크기 있음 전환을 `ResizeObserver`가 감지해 재측정한다.
