# Spec Delta

## Purpose

쇼핑 리뷰 분석 챗봇의 메인 화면으로, 데이터 인덱싱과 질의응답을 한 화면에서 수행하고 답변의 근거가 된 리뷰를 함께 보여주는 대시보드 동작을 정의한다.

## ADDED Requirements

### Requirement: 대시보드 레이아웃
시스템은 메인 페이지에 좌측 사이드바와 우측 채팅 영역을 함께 표시해야 한다(SHALL). 좁은 화면에서도 두 영역의 핵심 기능(인덱싱, 질문 입력)에 접근할 수 있어야 한다.

#### Scenario: 초기 화면 진입
- **WHEN** 사용자가 메인 페이지에 접속한다
- **THEN** 좌측에 사이드바가 보이고 우측에 상품 배너, 빈 메시지 스트림, 입력창이 보인다

#### Scenario: 좁은 화면
- **WHEN** 화면 너비가 좁아 두 영역을 나란히 둘 수 없다
- **THEN** 사이드바는 접거나 위로 쌓이며 인덱싱 버튼과 입력창은 계속 사용할 수 있다

### Requirement: 사이드바 헤더와 모드 배지
시스템은 사이드바 상단에 서비스 타이틀 "쇼핑 리뷰 AI 분석기"와 현재 데이터 모드 배지를 표시해야 한다(SHALL). 배지는 서버가 알려준 모드에 따라 "Mock 모드" 또는 "실데이터 모드"로 표시한다.

#### Scenario: Mock 모드 표시
- **WHEN** 상태 응답의 mode가 `mock`이다
- **THEN** 배지에 "Mock 모드"가 표시된다

#### Scenario: 실데이터 모드 표시
- **WHEN** 상태 응답의 mode가 `real`이다
- **THEN** 배지에 "실데이터 모드"가 표시된다

#### Scenario: 상태 조회 실패
- **WHEN** 상태 응답을 받지 못한다
- **THEN** 배지는 확인 불가 상태로 표시되고 나머지 화면은 계속 사용할 수 있다

### Requirement: 샘플 데이터 인덱싱 버튼
시스템은 [샘플 데이터 인덱싱] 버튼을 누르면 인덱싱을 요청하고 진행 중에는 스피너를, 성공 시에는 적재 건수가 포함된 완료 상태를, 실패 시에는 오류 메시지를 표시해야 한다(SHALL).

#### Scenario: 인덱싱 진행 중
- **WHEN** 사용자가 버튼을 누르고 응답이 아직 오지 않았다
- **THEN** 버튼에 로딩 스피너가 표시되고 버튼은 비활성화되어 중복 요청이 전송되지 않는다

#### Scenario: 인덱싱 성공
- **WHEN** 인덱싱 응답이 `success: true`이다
- **THEN** 완료 상태와 적재된 리뷰 건수가 표시되고 질문 입력이 활성화된다

#### Scenario: 인덱싱 실패
- **WHEN** 인덱싱 응답이 `success: false`이거나 네트워크 오류가 발생한다
- **THEN** 오류 메시지가 표시되고 버튼이 다시 활성화된다

### Requirement: 인덱싱 상태 복원
시스템은 화면을 열거나 새로고침했을 때 서버의 인덱싱 상태를 조회해 이미 인덱싱된 경우 완료 상태로 표시해야 한다(SHALL).

#### Scenario: 새로고침 후 복원
- **WHEN** 서버에 이미 리뷰가 인덱싱된 상태에서 페이지를 새로고침한다
- **THEN** 버튼 영역에 완료 상태와 적재 건수가 표시된다

### Requirement: 최근 분석 질문 히스토리
시스템은 사용자가 전송한 질문을 사이드바에 최신순으로 최대 10개까지 표시해야 한다(SHALL). 목록이 비어 있으면 빈 상태 안내를 표시한다. 항목을 누르면 질문 내용이 입력창에 채워지고 자동 전송되지 않는다.

#### Scenario: 질문 기록
- **WHEN** 사용자가 질문을 전송한다
- **THEN** 해당 질문이 히스토리 목록 맨 위에 추가된다

#### Scenario: 10개 초과
- **WHEN** 히스토리가 이미 10개이고 새 질문을 전송한다
- **THEN** 가장 오래된 항목이 제거되고 새 질문이 맨 위에 표시된다

#### Scenario: 항목 선택
- **WHEN** 사용자가 히스토리 항목을 누른다
- **THEN** 입력창에 해당 질문이 채워지고 포커스가 이동하며 요청은 전송되지 않는다

### Requirement: 상품 정보 배너
시스템은 채팅 영역 상단에 분석 대상 상품 정보 배너를 표시해야 한다(SHALL). 배너에는 최소한 상품명이 포함된다.

#### Scenario: 상품 배너 표시
- **WHEN** 메인 페이지가 표시된다
- **THEN** 채팅 영역 상단에 분석 대상 상품명이 담긴 배너가 보인다

### Requirement: 대화 메시지 스트림
시스템은 사용자 질문과 AI 답변을 구분되는 말풍선으로 시간순 표시해야 한다(SHALL). 새 메시지가 추가되면 스트림은 최신 메시지가 보이도록 스크롤한다. 메시지가 없으면 질문 예시가 포함된 빈 상태 안내를 표시한다.

#### Scenario: 빈 상태
- **WHEN** 대화가 시작되지 않았다
- **THEN** 사용하는 방법과 예시 질문이 포함된 안내가 표시된다

#### Scenario: 답변 대기
- **WHEN** 질문을 전송하고 답변이 아직 오지 않았다
- **THEN** 스트림에 답변 대기 표시가 나타난다

#### Scenario: 새 메시지 스크롤
- **WHEN** 새 메시지가 추가된다
- **THEN** 스트림이 최신 메시지가 보이는 위치로 이동한다

### Requirement: 참고 리뷰 아코디언
시스템은 AI 답변 하단에 근거 리뷰가 있으면 "참고 리뷰 N건" 배지와 아코디언을 표시해야 한다(SHALL). 아코디언은 기본으로 접혀 있고, 펼치면 각 리뷰의 평점, 작성자, 제목, 내용을 카드로 보여준다. 표시 건수는 응답의 sources 건수와 같고 최대 5건이다.

#### Scenario: 근거가 있는 답변
- **WHEN** 응답에 sources가 3건 포함되어 있다
- **THEN** 답변 하단에 "참고 리뷰 3건" 배지가 보이고 아코디언은 접혀 있다

#### Scenario: 아코디언 펼침
- **WHEN** 사용자가 배지 또는 아코디언 헤더를 누른다
- **THEN** sources 건수만큼 카드가 펼쳐지고 각 카드에 평점, 작성자, 제목, 내용이 표시된다

#### Scenario: 근거 없음
- **WHEN** 응답의 sources가 비어 있다
- **THEN** 아코디언과 배지는 표시되지 않는다

### Requirement: 질문 입력과 전송
시스템은 하단 입력창에서 Enter 또는 전송 버튼으로 질문을 전송해야 한다(SHALL). 빈 입력은 전송하지 않고, 답변 대기 중에는 추가 전송을 막으며, 인덱싱 전에는 인덱싱이 필요하다는 안내를 보여준다.

#### Scenario: 질문 전송
- **WHEN** 사용자가 질문을 입력하고 Enter를 누른다
- **THEN** 질문이 스트림에 추가되고 입력창이 비워진다

#### Scenario: 빈 입력
- **WHEN** 입력이 비어 있거나 공백뿐인 상태에서 전송을 시도한다
- **THEN** 요청이 전송되지 않는다

#### Scenario: 답변 대기 중 전송
- **WHEN** 답변을 기다리는 중에 다시 전송을 시도한다
- **THEN** 추가 요청이 전송되지 않는다

#### Scenario: 인덱싱 전 질문
- **WHEN** 인덱싱이 완료되지 않은 상태에서 전송을 시도한다
- **THEN** 인덱싱을 먼저 실행하라는 안내가 표시된다

### Requirement: 한글 IME 중복 전송 방지
시스템은 한글 등 IME 조합 중에 누른 Enter로 메시지를 전송해서는 안 된다(MUST NOT). 조합이 끝난 뒤의 Enter만 전송으로 처리하며, Shift+Enter는 줄바꿈으로 처리한다.

#### Scenario: 한글 조합 중 Enter
- **WHEN** 사용자가 한글을 조합 중인 상태에서 Enter를 누른다
- **THEN** 메시지는 전송되지 않고 조합만 확정된다

#### Scenario: 조합 완료 후 Enter
- **WHEN** 조합이 끝난 상태에서 Enter를 누른다
- **THEN** 메시지가 정확히 한 번만 전송된다

#### Scenario: 줄바꿈
- **WHEN** 사용자가 Shift+Enter를 누른다
- **THEN** 메시지는 전송되지 않고 입력창에 줄바꿈이 들어간다

### Requirement: 오류 표시
시스템은 채팅 응답이 `success: false`이거나 네트워크 오류가 발생하면 스트림에 오류 안내를 표시하고 다시 질문할 수 있어야 한다(SHALL).

#### Scenario: 답변 실패
- **WHEN** 채팅 응답이 `success: false`이다
- **THEN** 스트림에 응답의 error 내용이 담긴 오류 메시지가 표시되고 입력창이 다시 활성화된다

### Requirement: 아이콘 사용
시스템은 화면의 주요 요소(타이틀, 모드 배지, 인덱싱 버튼과 상태, 히스토리, 상품 배너, 사용자와 AI 구분, 전송 버튼, 아코디언 토글, 평점, 오류와 빈 상태)에 lucide-react 아이콘을 사용해야 한다(SHALL). 아이콘만으로 의미를 전달하는 버튼에는 접근 가능한 이름(aria-label)을 제공한다.

#### Scenario: 아이콘 버튼 접근성
- **WHEN** 전송 버튼처럼 아이콘만 있는 버튼이 렌더링된다
- **THEN** 스크린리더가 읽을 수 있는 이름이 제공된다

### Requirement: 모드 비의존 UI
시스템은 UI가 Mock Mode인지 Real Mode인지 스스로 판단하지 않고 서버 응답 값과 동일한 API 응답 규격만으로 동작해야 한다(MUST).

#### Scenario: 모드 전환
- **WHEN** 서버의 데이터 모드가 Mock에서 Real로 바뀐다
- **THEN** UI 코드 변경 없이 배지 표시만 바뀌고 인덱싱과 채팅은 동일하게 동작한다
